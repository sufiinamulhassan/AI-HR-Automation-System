# Product

## Register

product

## Users

HR admins, super admins, and recruiters at companies using this HR Bot platform to run recruitment end-to-end: posting jobs, screening resumes, running interviews, and managing the people/permissions/settings that keep the platform configured correctly. Super admins additionally manage platform-level configuration - roles & permissions, departments, workflow rules, integrations - that recruiters and HR admins never touch. These are busy, task-focused users working inside dense admin screens between other work, not browsing casually.

## Product Purpose

An AI-assisted recruitment and HR platform (resume screening, interview scheduling, candidate pipelines, coding assessments and offers) with a superadmin-controlled settings layer underneath it. Success looks like admins being able to scan, understand, and act on structured data (permission grids, user lists, configuration forms) quickly and with confidence that a change took effect.

## Brand Personality

Sleek, modern SaaS with an enterprise-serious edge: confident and clean rather than playful. Professional and understated - competence over decoration. The existing visual language (navy #14213d + amber #fca311, pill buttons, soft-shadowed cards, Jost display headings) should read as considered and premium, not flashy.

## Anti-references

- Dense, spreadsheet-like HTML tables with bare checkbox grids and no visual hierarchy - the exact complaint driving the current redesign work. Structured data should look designed, not dumped.
- Anything that skews playful, whimsical, or consumer-app in tone - this is enterprise software for people making access-control decisions.

## Design Principles

1. **Legibility over density** - admins scan permission/config screens under time pressure; group, label, and space information so the eye finds what it needs without parsing a grid cell-by-cell.
2. **Confidence in irreversible actions** - role/permission changes affect real user access; state changes (saving, saved, error) must be unambiguous.
3. **Consistent with the existing system** - reuse the established navy/amber palette, card and button patterns, and Jost/Outfit typography rather than introducing a parallel visual language for one page.
4. **Enterprise-serious, not decorative** - polish comes from spacing, hierarchy, and typography, not gradients, glass, or ornamental color.

## Accessibility & Inclusion

Standard WCAG AA: text contrast ≥4.5:1 (≥3:1 for large/bold text), all interactive controls (checkboxes, buttons, selects) keyboard-operable and properly labeled, visible focus states, and `prefers-reduced-motion` respected for any transitions/animations.
